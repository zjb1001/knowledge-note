## 核心观点

系统工程是一种跨领域的方法，助力成功系统的实现。**从功能而不是零件系统出发**，组织开发路径和结构。

正向开发时，四大架构**依次逐级开发**：

```
┌─────────────────────────────────────────────────────────┐
│                    功能架构 (Function)                   │
│              ↓ 分解功能，定义谁来实现                      │
│                    软件架构 (Software)                   │
│              ↓ 确定软件分层与通信机制                      │
│                    网络架构 (Network)                    │
│              ↓ 定义ECU间的连接方式                        │
│                    电气架构 (Electrical)                 │
│              ↓ 具体硬件实现                               │
└─────────────────────────────────────────────────────────┘
```

---

## 1️⃣ 功能架构 (Function Architecture)

**定义**: 对具备哪些功能及由谁（哪个系统/子系统/零部件）实现，进行整体规划。

**车辆功能领域划分**:

| 领域 | 英文 | 说明 |
|------|------|------|
| 驱动系统 | Propulsion Systems | 动力相关功能 |
| 车辆动态 | Vehicle Dynamics | 底盘、悬架控制 |
| 能量系统 | Fuel Systems | 燃油/电池管理 |
| 视觉系统 | Viewing Systems | 摄像头、显示屏 |
| 安全进出 | Security and Access | 门锁、无钥匙进入 |
| 车载娱乐 | Vehicle Infotainment | 多媒体、导航 |
| 乘员保护 | Occupant Protection | 安全气囊、安全带 |
| 主动安全 | Active Safety | AEB、LKA等ADAS功能 |

**关键产出**: 功能清单 + 功能分配矩阵（哪个功能由哪个系统实现）

---

## 2️⃣ 软件架构 (Software Architecture)

**定义**: 在项目早期做出的一组"难以在后期改变"的设计决策。

**包含两部分**:
- **静态结构**: 层次、模块划分、数据结构体 → 系统的骨架
- **动态行为**: 模块间通信、交互机制 → 系统的行为

### 软件架构演进三阶段

```
┌────────────────────────────────────────────────────────────┐
│  Stage 1: 早期嵌入式软件                                    │
│  ┌─────────────┐      ┌─────────────┐                      │
│  │  基础软件    │◄────►│  应用软件    │  ◄── 强耦合         │
│  │  (BSW)      │      │  (ASW)      │      不可移植        │
│  └─────────────┘      └─────────────┘                      │
├────────────────────────────────────────────────────────────┤
│  Stage 2: AUTOSAR CP (Classic Platform)                    │
│  ┌─────────────┐      ┌─────────────┐                      │
│  │  基础软件    │◄────►│  应用软件    │  ◄── RTE标准化接口   │
│  │  (BSW)      │      │  (ASW)      │      解耦           │
│  └─────────────┘      └─────────────┘      可移植         │
├────────────────────────────────────────────────────────────┤
│  Stage 3: AUTOSAR AP (Adaptive Platform)                   │
│  ┌─────────────┐      ┌─────────────┐      ┌───────────┐  │
│  │  基础服务    │◄────►│  中间件      │◄───►│   APP     │  │
│  │  (Services) │      │ (SOME/IP)   │      │           │  │
│  └─────────────┘      └─────────────┘      └───────────┘  │
│                                                            │
│  特征: 整车级软件接口标准化、SOA服务化、真正开放            │
└────────────────────────────────────────────────────────────┘
```

**发展趋势**: 基础软件(BSW) 与应用软件(ASW) **解耦合**

---

## 3️⃣ 网络架构 (Network Architecture)

**定义**: 用一个网络把各ECU全部连接起来并整体协调控制。

**与电气架构的关系**:
> 网络架构是电气架构**剥离了传感器、执行器等物理部件**后的纯通信视角。

**常见车载网络**:
- **CAN/CAN-FD**: 控制类通信
- **LIN**: 低成本车身控制
- **FlexRay**: 高速确定性通信
- **Ethernet**: ADAS/信息娱乐大数据量传输

---

## 4️⃣ 电气架构 (Electrical Architecture)

**定义**: 最底层的物理实现，包含控制器、线束、保险丝盒、传感器、执行器等。

**设计工作内容**:
- 蓄电池选型（容量、类型、布置）
- 控制器Pin脚定义
- 电源管理策略（休眠/唤醒、负载均衡）
- 零件成本管理
- 线束拓扑与包扎
- 保险丝盒与配电设计

## 正向开发流程总览

```
┌─────────────────────────────────────────────────────────────┐
│  需求分析                                                    │
│  └── 输入: 客户需求 + 技术基础 + 规范标准                     │
│  └── 分析: 任务环境 + 功能需求 + 性能约束                     │
│                      ↓                                       │
│  功能分析/分配                                                │
│  └── 分解功能到下一层级                                       │
│  └── 定义功能接口（内部/外部）                                 │
│  └── 输出: 功能架构                                           │
│                      ↓                                       │
│  设计方案                                                     │
│  └── 功能架构 → 物理架构                                      │
│  └── 定义系统概念、结构、单元                                  │
│  └── 输出: 软件/网络/电气架构                                  │
│                      ↓                                       │
│  系统分析与控制                                               │
│  └── 验证、评审、迭代优化                                     │
└─────────────────────────────────────────────────────────────┘
```

## 关键概念速查

| 概念 | 定义 |
|------|------|
| **功能** | 提供车辆运行或提高用户体验所需的功能 |
| **系统** | 一个设计要素的集合以支持一个或多个功能 |
| **单元** | 设计的最高层级单位，如子系统、软件单元 |
| **RTE** | Runtime Environment，AUTOSAR运行时环境接口 |
| **SOME/IP** | Scalable service-Oriented Middleware over IP |
| **SOA** | Service-Oriented Architecture，面向服务架构 |

---

## 学习要点

1. **四大架构的依赖关系**: 上层决定下层，下层支撑上层
2. **软件架构演进**: 从紧耦合 → AUTOSAR CP解耦 → AUTOSAR AP服务化
3. **电气架构是基础**: 所有上层设计最终都要落实在电气实现上
4. **正向开发思维**: 从功能出发，而非从零件出发
